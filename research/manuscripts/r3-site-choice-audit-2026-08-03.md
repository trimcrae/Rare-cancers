**That is an argument, and the observation that settles it was free.** The committed reharmonize frame
`results/nr4a3-pocket-reharmonize/release_rep0/fp_95_539ml58c/frame.pdb` is rep 0, frame 95 — the same
`(rep, frame)` the manifest names. Scored through the identical matcher in the same CI job:

| per-pocket druggability (all 15) | — | **identical dict** |
| matched pocket | 1, 0.259, J 0.6154, recovered 0.80, 3.478 Å | **identical** |
| per-pocket lining residues, alpha spheres, centroids | — | **identical** |
| measured CV Rg | 0.7612 nm | 0.7612 nm |
| verdict | `GATE_A_FAIL_BELOW_DSTAR` | `GATE_A_FAIL_BELOW_DSTAR` |

⚠ **One field is NOT run-stable, and it is worth naming so nobody quotes it precisely.** fpocket's `Volume`
came back as 590.3 / 496.5 Å³ on one CI run and 572.7 / 503.8 Å³ on the next, for the same two structures

**Three independent readings agree digit for digit** — this cross-check, the committed

re-score of the same frame in a separate process. The "re-extraction can disagree" caveat is **discharged
for this frame**, and the generation receptor turns out to have been inside the harmonized ensemble all
along — it was simply never looked up by index.

## F2 · ERRATUM — the generation frame's Rg is 0.7612 nm, not 0.7367

This is not a label. `release_frame_select.select_receptor_ensemble` chooses the primary receptor by
**minimising |Rg − target_rg|** over the druggable frames, so **Rg *is* the selection criterion.**

The metadynamics CV — Rg of the 10 Pocket-5 lining CA atoms about their centroid, `nr4a3_mdpocket.
_cv_rg_series`'s definition — recomputed directly from the frame's own coordinates:

| source | value |
|---|---|
| `nr4a3-release-druggable.json` → `selection_rg` | **0.7367 nm** |
| the paper, §"Dependency audit" | *"CV Rg 0.7367 nm"* |
| committed `release_rep0` series, frame 95 | **0.7612 nm** |
| **recomputed from `fp_95_539ml58c/frame.pdb`** | **0.7612 nm** |
| target (`TARGET_RG`, and `release-druggable-aws.yml`'s default) | 0.737 nm |

The recomputation reproduces the committed `cv_rg_nm` for **all 25** rep0 frames, which is what
`tests/test_r3_generation_frame.py` pins — so the CV definition is not in doubt and the disagreement is
with the **manifest**, not between two definitions.

**Why it matters:** at 0.7612 the generation frame sits **0.0242 nm** from target; rep0 frames 29 and 99
sit **0.0007** and **0.0006** away. A frame recorded at 0.7367 looks like the best possible match to the
selection rule; the frame that was actually shipped is not.

⚠ **What this does NOT establish.** Whether the *wrong frame was chosen* or the *right frame was
mislabelled* cannot be settled from what is committed: the pool that selection actually ran over was the
legacy `nr4a3-release-pocket/pocket_analysis_summary.json` for rep0, which is **not in this repo** (rep1
and rep2 are). Both readings are consistent with the evidence and the difference is not mine to resolve.

## (A) · SHOULD THE SITE BE POCKET 1 OR POCKET 2?

### F3.1 · What each cavity actually is

Reference lining set (prespecified, score-independent, mapped onto this structure):
**L406 T407 T410 P411 R412 · R481 I484 R485 · I531 L534**.

| | **pocket 1** — the frozen rule's site | **pocket 2** |
|---|---|---|
| druggability | **0.259** | **0.667** |
| reference residues recovered | **8 / 10** | 6 / 10 |
| Jaccard | **0.6154** | 0.375 |
| centroid vs reference | **3.478 Å** | 7.562 Å |
| volume (⚠ not run-stable — see F1) | ~570 Å³ | ~500 Å³ |
| alpha spheres | 63 | 40 |
| lining residues | 11 | 12 |
| **which reference residues** | L406 **T407 T410 P411 R412** R481 R485 I531 | L406 R481 **I484** R485 I531 **L534** |
| non-reference lining | N400 V403 R404 | L480 L524 Q525 N528 L529 S538 |
| Gate-A verdict if this were the site | `GATE_A_FAIL_BELOW_DSTAR` | `GATE_A_PASS` |

**Pocket 1 is the helix-3 face** of the reference set — it takes the whole contiguous 406–412 stretch.
**Pocket 2 is the helix-11/12 face** — it takes I484 and L534, which pocket 1 does not touch at all.

### F3.2 · They are NOT the same cavity seen through a different segmentation

This was the one reading under which the frozen rule's preference would look like a segmentation artefact,
and it is refused by the arithmetic:

- **4 shared lining residues** (L406, R481, R485, I531) out of 11 and 12
- **pairwise Jaccard 0.2105**
- **centroids 9.853 Å apart** — *further from each other than the gate's own 8.0 Å ceiling*, whose stated
  rationale is that *"a cavity centered a full pocket-width away is a DIFFERENT site regardless of residue
  overlap"*
- classified `OVERLAPPING_SUBPOCKETS`, not `SAME_CAVITY_RESEGMENTED`

⭑ **The real structure of the problem, stated plainly: in this frame the prespecified 10-residue reference
site is not one cavity.** It is split across two, and each cavity holds a different half. Both halves clear
the acceptance gate because the reference centroid sits *between* them (3.478 Å and 7.562 Å), while the
cavities themselves are 9.853 Å apart. **A composite gate designed to answer "is this cavity the site?"
was never designed to answer "which half of a split site is the site?"** — and that is the question this
frame poses.

### F3.3 · The frozen rule's answer, and why it stands

`pocket_tracking.match_pocket` orders accepted candidates by **frac_recovered → Jaccard → nearer centroid
→ druggability** (the last as *"a final deterministic tiebreak only, never as an acceptance criterion"*).
Pocket 1 wins on **all three** acceptance criteria. So the site is pocket 1, its druggability is 0.259, and
**the generation frame fails.**

⛔ **The defence against *"you chose the rule that fails it"* is checkable and it holds.** The ordering and
its three thresholds were frozen **2026-07-11**; this measurement is **2026-08-03**. Re-tuning them now —
in the matcher or in a helper — is precisely the outcome-selection defect the harmonized rerun exists to
remove, and it is the reason this audit reports what pocket 2 *is* rather than promoting it.

### F3.4 · ⚠ The choice is NOT local to this frame — measured, not asserted

The same ordering decides every frame of every species. Until now the committed artifacts recorded only
each frame's **winner**, so this could not be checked without another fpocket run.
[`pocket-accepted-candidates.json`](../modalities/pocket-accepted-candidates.json) now records **every
gate-accepted cavity in all 300 committed ensemble frames** (0 refusals, 257 s of free CPU), and its
frozen-rule column **reproduces all 12 rows of C04's independently computed table exactly** — which is what
makes the alternative column trustworthy.

Pooled over the three **unbiased** release replicas, ≥ D\* on the mapped site:

| species | frozen rule | if the most-druggable **accepted** cavity won |
|---|---|---|
| **NR4A3** | 44 / 75 (0.587) | 46 / 75 (0.613) |
| NR4A1 | 18 / 75 (0.240) | 23 / 75 (0.307) |
| NR4A2 | 21 / 75 (0.280) | 21 / 75 (0.280) |
| **NR4A3 − NR4A1 margin** | **0.347** | **0.307** (**−0.040**) |
| **NR4A3 − NR4A2 margin** | **0.307** | **0.333** (**+0.027**) |

⭑ **So the rule that would rescue the generation frame also reprices the paralogue-selectivity premise, in
both directions.** It narrows the NR4A1 margin and widens the NR4A2 one. Neither move is large, and that
is exactly why it had to be measured rather than guessed at: *"it only affects one frame"* is the
assumption this table refutes, and *"it would wreck selectivity"* is the overstatement it also refutes.

⛔ This table is a **sensitivity**, computed so the cost of a choice is visible. It is **not** a
recommendation and the frozen rule remains the rule.

### F3.5 · A collision worth recording: the design rule's two usable vectors live in pocket 2

[`steric-design-rule.json`](../modalities/steric-design-rule.json) (§10.1 row 24) found that of three
candidate substituent vectors only **I484** and **L534** clear the measured null ceiling, and that
**L406 → His/His** fires on clash but offers only 2.69 Å³.

In the generation frame, **I484 and L534 line pocket 2 and are absent from pocket 1**, while **L406 — the
vector that fails on volume — is one of the four residues the two cavities share.**

⚠ Scoped honestly: the design rule is computed on `results/nr4a3-matrix/nr4a3-opened.pdb`, a **different
structure**, so this is not a claim that the rule is wrong. It is the observation that **the site the
frozen rule selects and the sub-cavity the two surviving design vectors are anchored in are different
halves of the split reference set** — which no row of either lane could see on its own.

## (B) · WHAT WOULD A QUALIFYING GENERATION FRAME LOOK LIKE?

### F4.1 · 44 of 75 clear D\* **on the mapped site**, not on "any cavity"

The distinction matters and it holds: every committed `druggability_timeseries` row carries its own
`match` block, so a row's number **is** the cavity the harmonized gate accepted. All 75 unbiased release
frames are DETECTED (a matched site exists in every one); **44** of them reach D\*.

| replica | ≥ D\* on the mapped site |
|---|---|
| release_rep0 (the generation frame's own replica) | **14 / 25** |
| release_rep1 | 10 / 25 |
| release_rep2 | **20 / 25** |
| **pooled unbiased** | **44 / 75** |
| *(biased metadynamics, for contrast only)* | *17 / 25* |

### F4.2 · The program's own selector, re-run today

`release_frame_select.select_receptor_ensemble` — **the same function that chose frame 95**, called rather
than re-implemented — over today's harmonized per-frame series:

| pool | primary it returns | Rg | site druggability | offset from target 0.737 |
|---|---|---|---|---|
| **rep0 only** (the original pool's exact shape — `_load_summary_records` hardcodes `rep: 0` and reads one summary) | **rep0 frame 99** | **0.7376** | **0.621** | **0.0006** |
| all three release replicas | rep2 frame 21 | 0.7371 | 0.717 | 0.0001 |
| *the frame actually used* | *rep0 frame 95* | *0.7612* | *0.259* | *0.0242* |

⭑ **A qualifying generation frame does not require new MD, a wider pool, or a different protocol.** It is
four frames further along the same trajectory the program already ran, at essentially the same Rg the
selection rule targets, and it clears D\* with room to spare.

### F4.3 · What re-anchoring would cost — stated plainly, and it is not dollars

**`denovo_401`'s pose is defined against frame 95's coordinates.** A different receptor therefore means
**re-generating, not swapping**:

- **In dollars: $0.** The generative campaign is CPU/CI work. Cost is not the obstacle and must not be
  offered as one.
- **In the record: it invalidates the pose every downstream row inherits** — `R5`, rung `5b-T` site 1,
  `5c`, `5d`, and the paralogue ABFE legs all read a pose anchored to frame 95. A re-anchor does not
  *update* them; it makes them results about a molecule that no longer exists in the same place.
- **It changes the test article.** `denovo_401` is *"the paper's sole carried candidate … the molecule
  every downstream claim is about"*. A re-generated campaign returns a different molecule, and every
  §2.7/§2.8/§3/§5-Gate-4/SI §S1–S3 statement is then about something else.
- **It does not, by itself, repair anything.** `V3` left the pose pipeline's **site selection** missing on
  6 of 6 pairs (§10.1 row 4, held by another lane). Re-anchoring onto a druggable frame with an unrepaired
  site-selection step buys a new receptor for the same unresolved instrument.

⛔ **Whether to re-anchor is trimcrae's call.** It is a program decision about what the paper is about, not
a computation, and nothing here was re-generated.

## F5 · The mechanism, fixed — and it was never one workflow

`release-druggable-aws.yml` set **no `POCKET_MATCH`**, and `pocket_tracking.match_mode()` **defaults to
LEGACY** — the retired rule that picks the highest-**druggability** cavity in a window that is essentially
the whole LBD. That is how the generation receptor's manifest came to record **0.667**, which is *exactly
pocket 2's* score: **the legacy rule picked the cavity the harmonized rule declines.** Per CLAUDE.md §4 a
default that silently selects a retired rule is the same class as a populated field that was never
measured — the manifest looked complete and no reader could tell which rule produced its number.

**Fixed end to end**, because a workflow `env:` block alone would not have survived the hops:
`release-druggable-aws.yml` (new `pocket_match` input, default `harmonized`) →
`nr4a3_release_druggable_sagemaker.py` → `sagemaker_src/entry_release_druggable.py` →
`nr4a3_release_druggable.py`, which now **refuses** a legacy run unless `ALLOW_LEGACY_POCKET_MATCH=1` says
so out loud (reproducing the 2026-06-29 manifest stays possible), and records `mode_was_explicit` so
*"we chose harmonized"* is distinguishable from *"nothing set it and the default won"*.

**The guard is a census, not a memory.** [`pocket_match_wiring.py`](../modalities/pocket_match_wiring.py)
computes, from the files themselves, which lanes reaching `match_mode()` state their rule:

| | lanes |
|---|---|
| **wired** (4) | `release-druggable-aws.yml` · `r3-generation-frame-audit.yml` · `gpu-pocket-reharmonize-aws.yml` · `metad-replica-pocket-aws.yml` |
| ⛔ **still LEGACY-by-default** (4) | `gpu-mdpocket-aws.yml` · `gpu-calibration-aws.yml` · `gpu-8xtt-benchmark-aws.yml` · `fpocket-enumerate-aws.yml` |

⚠ **The unwired set is PINNED EXACTLY, not exempted** — fixing one, or gaining a fifth, both turn
`tests/test_pocket_match_wiring.py` red and force a deliberate edit rather than a silent baseline bump.
They are recorded rather than rewired here because each belongs to a lane whose artifacts are already
published, and silently changing what a committed number *means* is not mine to do.

⭑ **And one of the four is directly upstream of this incident:** `gpu-mdpocket-aws.yml` produces the
per-frame `druggability_timeseries` that STEP 0 selects its candidate pool from. The generation frame was
therefore selected from a legacy-scored pool **and** confirmed by a legacy rule — both hops of the chain
ran the retired classifier.
