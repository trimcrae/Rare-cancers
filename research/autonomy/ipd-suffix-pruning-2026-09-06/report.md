**Exact suffix pruning certifies 17 of 18 development releases, up from the previous frontier's 16, but still certifies none of the four stress releases.** It reduces unnecessary joint expansion on several fixed releases. It also exhausts the full charged-work budget on all stress releases, and one stress bound becomes weaker. This bounded experiment establishes a useful implementation improvement on these synthetic development inputs; it does not establish a useful research paper or justify continued solver polishing.

Generic novelty for imprecise logrank bounds, three-way certification and decision-focused queries is withdrawn under the coordinator's prior-art decision. The remaining conditional prospect concerns inversion of realistically rounded KM/risk information with unknown marginal histories and true ties. This grouped-time experiment supplies neither realistic uncertainty validation nor competent comparator, abstention or query-utility evaluation. No continuous-time guarantee, clinical efficacy, safety or therapeutic-window claim follows.

## Algorithm and frozen contract

The unchanged pre-execution [protocol](protocol.md) has SHA256 `3dd794df4bd391cbaecb5dc87596d33dc75badc173d5c8bf47ad986428711624`. The coordinator accepted it before release execution. [suffix.py](suffix.py) imports the unchanged original frontier's exact structural keys, tied-event U/V increments, rectangle union, outward suffix bounds and classification helpers. It retains the original locally admissible event/censor transition set, adding budget accounting within candidate loops.

Per-arm exact keys are `(time, risk, remaining events, rational KM)`. Each TRUE cache entry stores an actual full continuation. FALSE is written only after all locally admissible successors prove false, including the case of an empty exhausted successor set. Missing entries are UNKNOWN. An interruption unwinds without writing false for any interrupted frame; previously completed descendants remain cached. The query API uses `None` for UNKNOWN, `False` for proven infeasibility and a tuple for a real continuation, including the empty terminal tuple.

Initial suffix queries seek full compatible arm paths to establish nonemptiness. Before a marginal child participates in joint expansion, its suffix is queried. Only FALSE prunes. If a query is UNKNOWN because the global budget fires, traversal stops with the active parent retained; an interruption in the initial search retains the initial joint state. Untouched frontier states, already generated children and terminal boxes also remain. The inherited exact-key rectangle argument consequently covers every compatible full history. Terminal/initial actual paths establish nonemptiness; a box alone never certifies. True simultaneous events retain the ordinary tied-event variance formula. No no-ties shortcut is introduced.

All search work shares 12 seconds, 200,000 work units, 100,000 joint transitions, 20,000 joint states, 100,000 cached suffix entries and a 64 MiB traced-allocation cap per release. Work counts include entered suffix calls and cache hits, candidate event counts, censor successors and joint pairs. An attempted charge at an exhausted cap interrupts before that operation; failed descendant searches that ran before the cap retain their charges. Initial feasibility is included, with no free preprocessing. Time/memory checks occur at charges/cache insertion, and outer-bound aggregation is subsequently completed and included in measured end-to-end time and peak memory. The cap constrains search, not the final act of preserving/reporting its frontier. Peak memory is traced Python allocation, not OS RSS. All six interrupted release runs hit the work cap; none reached a time, state, cache or memory cap.

These limits differ from the saved original solver's separately allotted 8+2+2 seconds and its uncharged feasibility/generation work. The saved-host timing comparison is descriptive and is not a controlled speed benchmark. Pruning counts are occurrences of rejected marginal transitions; repeated encounters can share a cache key, and one rejected A transition can prevent many joint pairs. They are not unique patient histories or distinct states.

## Actual verification

[verify.py](verify.py) independently enumerates remaining subject-category multisets for every examined tiny cache key, without using the solver's transition generator. Its 98 distinct suffix enumerations support 359 false-cache emptiness checks and 2,039 actual true-continuation membership checks. It separately reconstructs each returned full witness as subject records and reproduces the released summaries and tied-event score.

Using the existing 56 tiny subject multisets and ten coarse release groups, 320 complete/forced runs perform 17,632 individual-history coverage checks. Every compatible pair has a retained region with the identical exact structural key and enclosing prefix U,V. Two hundred forced suffix interruptions verify UNKNOWN behavior, including 24 interruptions immediately after a false child and before completion of the parent successor loop. The tests exercise entry within recursion, partially generated joint children with retained active parents, cache/work/time/memory/state/transition caps, absent witnesses, zero variance and genuinely incompatible releases. Explicit API checks distinguish UNKNOWN `None`, false `False` and terminal true `()`.

All 18 saved exact development oracle extrema fall inside the new outer intervals. Every emitted witness in the 22 release outputs independently reproduces its release and score. The checks passed in 1.178 seconds; [verification.json](verification.json) and the original [verification log](verification-run.log) contain the results. These are worker-implemented independent arithmetic/subject-enumeration checks, not an independent ultra review. The coordinator's separate finished-packet verification is not claimed here.
