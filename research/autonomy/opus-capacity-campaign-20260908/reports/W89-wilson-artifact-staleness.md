### Per-module tolerance rationale (answering W80's caution)

A single global tolerance would have been wrong in both directions. `hormone_partner_map` and `emc_locoregional_eligibility` publish at radically different granularity (unrounded float vs 0.1 pp) from the **same** z; a global 1e-4 would have been vacuous for the former and over-tight for `emc_fusion_partner_pooling`. The method used instead: **compare at each module's own published granularity** — round the recomputation exactly as the module does, then require equality (tolerance 0.0) wherever the artifact records exact integer inputs; loosen only where the artifact's *inputs* are themselves rounded (module 1: `pooled_fraction` 6 dp / `effective_n` 2 dp → 1e-4; module 2: `allele_frequency` 4 dp → 1e-3). For `emc_fusion_partner_pooling` the 0.1-pp concern does not arise as a tolerance at all: its own `check()` builds the reference in memory and compares the built document, so both sides carry the identical rounding.
