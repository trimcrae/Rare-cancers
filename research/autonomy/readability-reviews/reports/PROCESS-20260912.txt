## PROCESS-R1: omission of an applicable supplement bypasses coverage

The helper checks every artifact that the review receipt happens to list and requires the registered main document to appear. It has no independent source for which supplementary prose must also appear. A receipt listing only the main manuscript passes even when an applicable supplement has changed or has never been reviewed. This conflicts with the README's explicit requirement for every outgoing prose source, including applicable supplements.

The existing missing-SI test deletes an SI file that remains named in `receipt.artifacts`. That tests availability of a declared artifact, not completeness of the declared scope. Removing the SI entry from the receipt bypasses that check.

An in-memory probe used a valid synthetic receipt with main-only coverage, a separate modified/unreviewed supplement, all six checks true and a bound nonempty report. `verify_review` returned `True` with “covers 1 unchanged prose artifact(s).” The read callback visited only the receipt and report; it never read the omitted supplement. This was a synthetic probe and is not approval evidence for any actual paper.

Required repair: derive mandatory outgoing prose paths from a separately maintained, candidate-bound inventory rather than from the receipt itself. Require the registered main to belong to that inventory and require every inventory member to have a reviewed hash and section coverage. Missing inventory, unknown paper, omitted SI and malformed inventory must fail closed. Govern the inventory like the helper so changing the required scope requires a declared process amendment. Add a regression that removes SI from the receipt while retaining it in the authoritative inventory.

Root's announced approach is `research/autonomy/editorial-prose-inventory.json`, schema `emc-editorial-prose-inventory/1`, with a papers map naming each required outgoing prose source. The initial canonical/frozen path inventory should continue to reject review receipts bound only to new replacement directories. Scope must be explicitly reconciled when the release/endpoint is promoted. This design is suitable; acceptance awaits reading its implementation.

## What is correctly enforced in the initial implementation

The new clause no longer treats a sentence-length score as sufficient evidence of clarity. It requires a distinct reviewer identity, nonempty model/provenance description, five reader explanations, all six actual check outcomes, a passing decision and an empty blocker list. It rejects the writer's own identity and binds the retained report and each named artifact by SHA256. The report, receipt and listed artifacts are read at the requested candidate revision, so a convenient working-tree receipt cannot approve older unreviewed bytes. Unrelated commits can reuse identical reviewed artifacts.

The old sentence/caution safeguards remain in addition to the LLM record. The new documentation appropriately states that these metrics do not prove clarity and the checker cannot prove reviewer honesty or scientific truth. It requires root to read the real report and preserve execution provenance; a fabricated Boolean receipt would violate that contract even if its shape is syntactically valid. The reviewer identity and execution-evidence fields are coordinator-attested records, not cryptographic identity attestations. That stated limit is not a second code defect.

The new helper is included in the amendment guard's governed file set. No enforcement threshold was relaxed. The test file covers stale listed artifacts/reports, wrong paper, self-review, missing explanations, failed checks, unresolved blockers and pinned-revision receipt retrieval. The coverage-omission gap above is the one material new defect found.
